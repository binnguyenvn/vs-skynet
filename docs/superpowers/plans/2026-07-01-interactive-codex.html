Interactive Codex Mode — Implementation Plan

Second run mode for the codex adapter: drive codex as a live TUI in a VSCode terminal — multi-turn steering with pause/resume in one session — built as a CLI-agnostic core (src/adapters/interactive/) plus one codex profile, proven by a real-CLI integration test alongside the existing runCodex.

Global constraints

  • Additive only — runCodex / codexAdapter.run unchanged.
  • Launch argv: codex -C <cwd> [-m <model>] -s <sandbox> -a never -c disable_paste_burst=true -c 'tui.keymap.composer.submit="tab"' -c 'tui.keymap.composer.queue="ctrl-q"', submit key "\t" — probe-verified.
  • Default timeouts: turnTimeoutMs 300000, readyTimeoutMs 30000 (turn-1 only, one retry ping on expiry).
  • Crash detection (ps -Ao pid,ppid,comm descendant walk) is macOS/Linux only in v1.
  • Mailbox reader is a poll loop, not vscode.FileSystemWatcher (groomed — one mechanism, not two).
  • Protocol bootstrap never overwrites a real instruction file; appends a marker block, strips it on dispose().
  • Real-CLI integration test gated behind CODEX_INTERACTIVE_E2E (mirrors the existing CODEX_E2E convention).

US-1: Interactive Codex Mode

Call codexAdapter.runInteractive({cwd, workerId}), get an InteractiveSession, send() turns that pause or complete, watch a sparse WorkerEvent stream, read harvested sessionId/usage from codex's own rollout JSONL, and dispose() cleanly — proven by unit tests against a fake terminal transport plus an opt-in real-CLI integration test.
