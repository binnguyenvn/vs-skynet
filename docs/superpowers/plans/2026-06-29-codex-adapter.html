Codex Adapter — Implementation Plan

Standalone codex CLI bridge: spawn codex exec --json, stream typed events, resolve a terminal status with error classification, and expose a small webview smoke UI.

2026-06-29 TDD · frequent commits spec: codex-adapter-design

Global constraints

  • Verified against codex-cli 0.142.3; invocation codex exec --json --skip-git-repo-check -s <sandbox> -C <cwd> [-m <model>] "<prompt>".
  • Child stdin MUST be 'ignore' + prompt as argv — else codex blocks on the stdin notice.
  • Default sandbox read-only. Codex only: no shared type, no fallback, no full step-function panel.
  • Core adapter code under src/adapters/codex/; the only webview changes are testCodex/codexLog, the HelloView button/log panel, and panel message handling.
  • Tests under src/test/ via the existing runner.
  • Real-CLI test gated behind CODEX_E2E so npm test doesn't burn quota.

US-1: Codex adapter

Call runCodex({prompt, cwd}), iterate typed events, await a CodexResult with success/failed/cancelled (failures classified). Proven by deterministic parser/classifier unit tests plus an opt-in real-CLI integration test.
