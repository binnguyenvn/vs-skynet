Interactive Agy Mode — Implementation Plan

Second run mode for the agy adapter: drive agy as a live TUI in a VSCode terminal, reusing the CLI-agnostic core already built and shipped for interactive codex (src/adapters/interactive/). Adds exactly two new things: a shared SessionInfoProbe fallback (for CLIs with no readable session transcript) and agyInteractive: InteractiveCliProfile — proven by a real-CLI integration test alongside the existing runAgy.

Global constraints

  • Additive only — runAgy / agyAdapter.run unchanged.
  • Launch argv: agy --dangerously-skip-permissions --new-project [--model <m>] --add-dir <cwd> (no --print, no --sandbox), submit key "\r" — probe-verified.
  • Instruction file GEMINI.md; never overwritten (reuses the existing marker-append/strip bootstrap, unchanged).
  • harvest() always returns {} — no confirmed agy transcript. sessionId comes only from the new sessionInfoPrompt fallback (SessionInfoProbe).
  • Default timeouts (inherited): turnTimeoutMs 300000, readyTimeoutMs 30000. New: sessionInfoTimeoutMs 90000, injectable for fast tests.
  • Crash detection macOS/Linux only in v1 (inherited, unchanged).
  • Real-CLI integration test gated behind AGY_INTERACTIVE_E2E (mirrors AGY_E2E / CODEX_INTERACTIVE_E2E).

US-1: Interactive Agy Mode

Call agyAdapter.runInteractive({cwd, workerId}), get an InteractiveSession, send() turns that pause or complete, watch a sparse WorkerEvent stream, get a harvested sessionId via the session-info fallback (no usage — agy has none), dispose() cleanly, and exercise all of it through a webview smoke button — proven by unit tests against a fake terminal transport plus an opt-in real-CLI integration test.
