Skynet — Product Roadmap

Three levels: Phases are the build stages (MVP, then Post-MVP); each Epic is a subsystem (a card below); each Feature is a capability inside an Epic, carrying a status badge. Skynet turns raw models into dependable Workers (Agent + Harness + Soul) and orchestrates them into a delivery team inside VSCode.

Two principles drive every layer: never blocked by one provider (multiple CLI adapters first) and every layer proves itself via a live step-function state machine. Use the legend to filter by status.

Phase 1 — MVP · Epic

Adapters

Three CLI bridges built first so no single provider's limit can block downstream work. Pure single-responsibility bridges — resilience lives elsewhere.

Codex adapter
Concrete-first openai x cli bridge: spawn codex exec --json, parse JSONL into codex-specific events, classify errors (limit/transport/terminal). Proven by a real integration test. No shared type yet.
Open
Claude Code adapter
anthropic x cli bridge. Verify flags/auth/event shapes against the real CLI before planning.
Open
Antigravity (agy) adapter
google x cli bridge. Unconfirmed tool — real --help/run check is the first step of its plan.
Open
Normalized WorkerEvent stream
One typed, CLI-agnostic event shape (reasoning, tool-call/result, file-change, log, usage) across all adapters.
Open
Error classification (limit/transport vs terminal)
Each adapter classifies failures so the later fallback layer has a signal. No fallback logic in the adapter itself.
Open

Phase 1 — MVP · Epic

Harness

The control layer plus the live step-function panel — the permanent feature that doubles as every layer's acceptance proof.

Step-function state-machine panel
The permanent live panel: each step shows Success/Failed/Cancelled/In-Progress. Doubles as every layer's proof.
Open
Observability
Parse the full event stream (tool calls, logs, decisions) and render it into the panel.
Open
Verification gate
Lint/test/judge must pass before a run can claim done; a fake done turns the step red.
Open
Guardrails & caps
Sandbox modes, step/token caps, wall-clock timeout, cancel.

Tools / Plugins

Plugin catalog

Install into CLIs
End-user clicks Install; the pack is installed into codex/claude/agy so the agent can use it.

Per-task harness gating
The harness denies installed tools/plugins to tasks that don't need them — installed is not always-on (least privilege).
