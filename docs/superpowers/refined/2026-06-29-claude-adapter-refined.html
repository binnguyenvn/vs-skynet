US-1: Claude Code adapter — run a task through claude and get a typed result

What it does

Lets the rest of the extension run a prompt through the Claude Code CLI and receive a live stream of typed events (start, assistant text, thinking, tool calls, token/cost usage) plus a single clear outcome (succeeded / failed / cancelled), instead of raw terminal JSONL.

Scope
  • In: the src/adapters/claude/ module — event types + JSONL mapper (events.ts), error classifier (classify.ts, copied from codex), and runClaude() (claude-adapter.ts) spawning claude -p --output-format stream-json --verbose. Fast fake-CLI tests + a real-CLI proof gated behind CLAUDE_E2E.
  • Out: any UI; multi-turn/resume, --json-schema, --input-format stream-json, images; shared adapter types + shared-classifier extraction.
Acceptance
  • Fake claude emits init + text + result is_error:false, exit 0 → success, started+message streamed, hook noise → unknown, usage carries costUsd.
  • Gotcha: subtype:"success" with is_error:true ("Not logged in"), exit 0 → failed, errorClass: 'terminal'.
  • result text with 429 → failed, errorClass: 'limit'.
  • mapClaudeLine fans an assistant line to message/thinking/tool_call/usage; system/init → started; hook subtypes → unknown; result → usage (with cost).
  • CLAUDE_E2E=1 npm test: real reply-pong succeeds (usage present); a cancelled run → cancelled.
Tasks

Task 1 (event types + JSONL mapper) · Task 2 (classifier) · Task 3 (runClaude + proofs)

US-2: Test Claude webview smoke UI — prove the adapter from the panel

What it does

Adds a Test Claude button and a Claude log panel to the existing Skynet webview so a developer can click once and watch a real claude run stream its output, tool calls, usage, and final status inside the extension.

Scope
  • In: the testClaude/claudeLog protocol entries, streamClaudeTestToWebview host bridge, extension-host handler, React button + log panel. Fast bridge unit test (fake run) + manual click-through.
  • Out: any production worker/observability panel (smoke test only); changes to the codex/agy buttons.
Acceptance
  • Bridge unit test: fake ClaudeRun (started/thinking/tool_call/message/usage → success) posts exactly Starting Claude test..., started session … (model), thinking: …, tool …, the text, usage in=… out=… cacheW=… cacheR=… cost=$…, done success.
  • Manual: clicking Test Claude streams lines ending in done success; button disables while running, re-enables on done/error.
  • npm test stays green (pretest compiles + lints the wiring).
Tasks

Task 4 (protocol + bridge) · Task 5 (host + React view wiring)
